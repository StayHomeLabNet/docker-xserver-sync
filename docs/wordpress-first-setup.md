# WordPress初回セットアップ仕様

更新日: 2026-11-07

## 目的

ローカルDocker環境で動作しているWordPressを、WordPressやMySQLがまだ用意されていないXServerへ、専用ウィザードで初回配置できるようにする。

通常のファイル同期と初回セットアップは別機能とし、初回セットアップでのみMySQLへの書き込みを許可する。

## 完了条件

次をすべて満たしたとき、「空のXServerへの初回セットアップ完了」とする。

1. ローカルWordPressのファイルとDBダンプを自動取得できる。
2. XServer APIでMySQLデータベース、MySQLユーザー、アクセス権を作成できる。
3. APIを使わない場合は、サーバーパネルで作成したDB情報を入力して続行できる。
4. WordPressファイルを公開先へ配置できる。初回配置では `wp-config.php` と `wp-content/uploads/` も移行対象にできる。
5. XServer用の `wp-config.php` を生成し、DBパスワードを画面、SQLite、操作ログに残さない。
6. SQLを対象DBへインポートできる。
7. ドメインが変わる場合、PHPシリアライズ値を壊さない方法でURLを置換できる。
8. トップページと `wp-login.php` のHTTPS確認が成功する。
9. 実行結果と手動確認項目を表示する。

## 標準フロー

1. **ローカル診断**
   - WordPressルート、`wp-config.php`、`wp-content`を検出する。
   - Docker Composeの実行状態とDBコンテナを確認する。
   - WordPress、PHP、DBのバージョンとローカルURLを取得する。
2. **XServer事前診断**
   - SSH/SFTP、ホスト鍵、リモートルート、対象ドメインを確認する。
   - API方式では、XServer APIキーの対象サーバーとMySQL書き込み権限を確認する。
   - 作成済みDB方式では、サーバーパネルに表示された完全なDB名、MySQLユーザー名、MySQLホスト、パスワードを入力する。
   - 作成済みDBへの接続とテーブル数を確認し、空でない場合はSQL転送前に停止する。
   - 公開先が空か、初期ファイルだけかを表示する。
3. **移行パッケージ作成**
   - DBを一貫性のあるSQLへダンプする。
   - ファイルとSQLのSHA-256マニフェストを作成する。
   - 旧URLと新URL、テーブル接頭辞、サイトサイズを表示する。
4. **最終承認**
   - 対象サーバー、ドメイン、ファイル数、SQLサイズ、作成するDB名とユーザー名を表示する。
   - 対象ドメインの再入力を必須にする。
5. **適用**
   - API方式ではDBとユーザーを作成し、権限を付与する。
   - 作成済みDB方式では、DBやユーザーの作成・変更・削除を行わない。
   - SQLをインポートし、安全なURL置換を行う。
   - WordPressファイルを転送し、XServer用 `wp-config.php` を最後に公開する。
6. **検証**
   - ファイルハッシュ、DBテーブル数、`home` / `siteurl`、HTTPS応答を確認する。
   - WordPressのDB更新が必要な場合は、管理画面へのリンクと確認事項を表示する。

## 安全性

- APIキーとDBパスワードはOS資格情報ストアへ保存し、SQLiteには参照名だけを保存する。
- APIキーは対象サーバーを限定し、MySQLに必要な最小権限を推奨する。
- 既存DBと既存DBユーザーは上書き・削除しない。名前が重複した場合は停止する。
- 既存テーブルがあるDBへのインポートは禁止する。
- 作成済みDB方式でもDBパスワードは永続保存せず、SSH先の一時設定ファイルは権限`0600`で作成し処理後に削除する。
- セットアップ途中で失敗した場合、作成したリソースと公開済みファイルを記録し、自動削除せず復旧手順を表示する。
- URL置換は単純なSQL文字列置換ではなく、WordPressのシリアライズ値に対応した方法を使う。

## 実装順序

### フェーズ1: XServer API基盤

- APIキーのOS資格情報ストア保存
- APIキーと対象サーバーの診断
- DB作成、DBユーザー作成、権限付与
- 同名リソースの検出と安全な停止

### フェーズ2: ローカルWordPress移行パッケージ

- Docker Compose構成と `wp-config.php` からDB接続先を検出
- `mysqldump` の実行と秘密情報のマスク
- ファイル・SQLマニフェスト

### フェーズ3: 初回配置エンジン

- SQLインポート
- `wp-config.php` 生成
- 初回用ファイル配置（`uploads` を含む）
- URL置換
- ハッシュ、DB、HTTPSの完了検証

### フェーズ4: GUIウィザード

- 診断、入力、承認、進捗、完了画面
- APIを使わない作成済みDB入力、接続確認、空DB確認
- 失敗時の再開・復旧手順表示

## 後回しにする機能

- 既存本番WordPressへの日常的なDB同期
- 本番DBからローカルへの取り込み
- 定期実行、無人実行
- 既存DB・既存ファイルへの破壊的な上書き
- プラグイン固有のDBアップグレード自動実行
