## 1. 全体設計思想と安全機能

Docker → XServer Sync は、ローカルの Docker コンテナ環境と XServer 本番環境の「差分」を埋め、事故を起こさずに同期することを目的として設計されています。

### 主な安全設計
- **読み取り専用ドライラン**: サーバーに変更を加えることなく、追加・更新・削除・競合ファイルを事前に完全走査。
- **4段階自動同期パイプライン**: 「ドライラン」→「計画の再検証」→「変更前ファイルの自動バックアップ」→「明示承認後の安全同期」を1クリックで完結。
- **アトミック書き込み**: ファイル転送時は一時ファイル（`.new`）へ転送した後にリネームするため、通信断や強制終了時もファイルが破損しません。
- **自動除外と本番データ保護**: `.git`、`.env`、開発用 `compose.yml`、`node_modules/` などの秘密・不要ファイルは既定で除外。サーバー上の `uploads/` や `storage/` などの動的ファイルは削除・上書きから保護されます。
- **OS資格情報ストア連携**: SSH接続先の確認コード（ホスト鍵 SHA-256 フィンガープリント）は平文で保存せず、Windows 資格情報マネージャー、macOS キーチェーン、Linux Secret Service に安全に保管。中間者攻撃（MITM）を確実に防止します。

## 2. 動作環境と事前準備（XServer 側・ローカル側）

### 動作環境
- **対応OS**: Windows 10 / 11 (x64), macOS 12+ (Apple Silicon arm64 / Intel x86_64), Linux (x86_64)
- **ネットワーク**: XServer の SSH ポート（通常 `10022`）へ接続可能なインターネット環境

### XServer 側の準備手順
1. **XServer サーバーパネルへログイン**:
   - 「SSH設定」を開き、SSH接続を **「ON（有効）」** に設定します。
2. **SSH 鍵の取得**:
   - 「公開鍵認証用鍵ペアの生成」でパスフレーズを指定して鍵を生成し、秘密鍵（`.key` ファイル）を PC にダウンロードします。
3. **接続情報の確認**:
   - 「SSHソフト設定」画面で以下を確認します：
     - **SSHホスト**: `SERVER_ID.xsrv.jp`
     - **SSHユーザー**: `SERVER_ID`（サーバーID）
     - **SSHポート**: `10022`
     - **確認コード**: `SHA256:...` から始まるホスト鍵フィンガープリント

### ローカル（Docker / PC）側の準備
- 同期元フォルダとして、PC上のローカルパスを指定します。
- `compose.yml` 内で `volumes: ./src:/var/www/html` と指定されている場合は、PC上の `./src` の絶対パスを指定します。

### 操作ボタン一覧
- **新規…**: 新規プロジェクトを作成します。
- **複製…**: 選択中のプロジェクト設定を引き継ぎ、新しいプロジェクトとして複製します。
- **編集…**: 接続情報やパスマッピング、保護・書き込み先設定を編集します。編集ダイアログ内にも「複製…」ボタンが用意されています。
- **削除**: 保存済みプロジェクト設定を削除します（ローカル・リモートの実体ファイルは一切削除されません）。
- **安全性確認**: XServer 上に残存している一時ファイル（`.new`）や期限切れバックアップを検出・一括掃除します。
- **履歴…**: 過去の同期・リストア履歴を閲覧し、バックアップからのロールバックを実行できます。
- **安全同期を自動実行**: 推奨される同期方式です。ドライラン・再検証・バックアップ・反映の全自動パイプラインを実行します。
- **自動実行設定…**: 選択中プロジェクトの自動実行設定（バックアップ方針・`REMOTE_ONLY` 扱い・HTTPS確認・安全上限）を開きます。ボタン左側には現在の設定概要が常時表示されます。
- **読み取り専用ドライラン**: サーバーを変更せずに差分のみを取得・一覧表示します。
- **処理を停止**: 同期・セットアップ処理を直近の安全なファイル境界で中断します。

## 4. サイト種別ごとの設定と運用ガイド

### 4-1. 独自 PHP サイト
WordPress や Laravel 以外の PHP サイトです。

1. **設定手順**:
   - サイトの種類に **「独自 PHP（上記以外）」** を選択。
   - 同期フォルダの **「XServer側の保護対象を設定…」** を開きます。
   - **「XServerから一覧を取得…」** では、まず同期先ルート直下のファイル／フォルダだけを表示し、各項目の左に表示されるチェックボックスで保護対象を選択できます。チェックボックスはmacOSのダークモードを含む各OSテーマで表示されます。
   - 配下の項目を個別に選びたい場合は、一覧画面の **「サブフォルダも含めて取得…」** を押してください。フォルダ自体を選ぶと配下全体が保護されるため、その場合はサブフォルダの取得は不要です。
   - 保護対象は同期走査から除外されます。同期処理では保護フォルダの配下へ入らず、保護ファイル／フォルダの内容読み取り、ハッシュ比較、バックアップ、復元、アップロード、削除を行いません。保護パスを識別して避けるため、親フォルダの一覧取得だけは行います。
   - `uploads/`、`storage/`、`cache/`、`logs/`、`tmp/` は自動保護されます。
   - `userfiles/` や `data/sessions/` など、サイト固有の本番書き込み先があれば追加し、**「本番で書き込まれる場所を確認し、上記の自動保護と追加一覧に漏れがないことを確認しました」** にチェックを入れて保存します。
2. **日常の同期**:
   - 「安全同期を自動実行」を押すだけで、保護フォルダを維持したままプログラムコードのみを安全に同期します。

---

### 4-2. WordPress サイト
WordPress サイトの初回移行と日常同期をサポートします。

#### 初回セットアップウィザード
Docker 環境の WordPress を空の XServer ドメインへ移行します。
1. **事前準備**:
   - Docker の MySQL から `.sql` ダンプファイルを出力しておきます。
   - XServer のサーバーパネル「MySQL設定」で空のデータベースとユーザーを作成します（または XServer API を利用）。
2. **ウィザードの実行**:
   - 上部パネルの **「セットアップを開始…」** をクリック。
   - **SQLファイルの選択**: 用意した `.sql` を指定。
   - **対象ファイルの選択**: コアファイル、テーマ、プラグイン、uploads の転送対象を確認。
   - **データベース情報**: MySQLホスト（通常 `localhost`）、DB名、ユーザー、パスワード、公開URLを入力。
   - **PHP CLI バージョン**: サーバーパネルの PHP バージョンに合わせます（既定: PHP 8.3）。
   - **実行**:
     - DBテーブルの重複チェック（既存テーブルがあれば安全のため中断）
     - SQLダンプの転送・インポート
     - WordPressファイルの転送
     - `wp-config.php` の自動生成・配置
     - WP-CLI による URL 置換（ローカル URL → 本番ドメイン URL）
     - 初期 `index.html` の自動削除
     - HTTPS ヘルスチェック（トップページおよび `/wp-login.php` の 200 OK 確認）

#### 日常の同期
- 初回セットアップ完了後は、通常の「安全同期を自動実行」を使用します。
- `wp-config.php` や `wp-content/uploads/` は保護対象として維持され、ローカルの変更（テーマやプラグインの更新）のみが安全に反映されます。

### 4-3. Laravel サイト
Laravel サイトの分割配置・初回デプロイ・差分同期をサポートします。

#### 推奨ディレクトリ構成
セキュリティのため、Web公開フォルダとアプリケーション本体を分離して配置します。
- **Laravel本体（アプリルート）**: `/home/SERVER_ID/example.com_app`
- **公開ディレクトリ（公開ルート）**: `/home/SERVER_ID/example.com/public_html`

#### 初回セットアップウィザード
1. **ウィザードの起動**:
   - 画面上部パネルの **「セットアップを開始…」** をクリック。
2. **設定項目の入力**:
   - **DB接続方式**: 作成済みDBの指定（ホスト、DB名、ユーザー、パスワード）。
   - **本番APP_URL**: `https://example.com`
   - **PHP CLIバージョン**: 対象ドメインのPHPバージョンを選択（例: `/usr/bin/php8.3`）。
   - **マイグレーション**: `artisan migrate --force` の実行有無。
3. **自動実行内容**:
   - リモート高速一括スキャン（サーバー側配置状況を 0.2 秒で確認）
   - 本体ファイルおよび public ファイルの転送
   - 本番用 `.env` の自動生成・配置
   - APP_KEY 生成 (`php artisan key:generate --force`)
   - `storage` ディレクトリのパーミッション設定
   - シンボリックリンク作成 (`public/storage` → `storage/app/public`)
   - マイグレーション実行
   - HTTPS ヘルスチェック

#### 高速スキップ機能（v0.3.1+）
- Laravel の初回セットアップでは、SSH経由でリモートの配置済みファイルを一括スキャンします。すでに転送済みの同一ファイル（サイズ・更新日時一致）は自動でスキップされるため、数千〜1万件のファイルがあっても約20秒で高速同期が完了します。

### 4-4. 静的サイト（HTML / ビルド済み）
静的HTML、CSS、JavaScript、画像、または Astro / Next.js（`out/`）/ Hugo / Vite などのビルド済み成果物を同期するためのモードです。

1. **特徴と既定の挙動**:
   - **自動保護パスなし（確認チェック不要）**: `uploads/` や `wp-content/uploads/`、`wp-config.php`、`.htaccess` 等が自動で保護スキップされることはなく、ビルド済みアセットや静的サイト用 `.htaccess` もそのまま同期対象になります。
   - **公開ディレクトリへの配慮**: `.git/`、`.env`、`node_modules/`、`docker-compose*.yml`、`.DS_Store` 等の秘密・開発ファイルのみを除外し、`/docs/` や `/test/`、`/README*`、`/LICENSE*` 等の公開フォルダ・ファイルは除外しません。
   - **XServer側の任意保護**: XServer上に残したいファイル／フォルダ（例: `.htaccess`、`.well-known/`、`cgi-bin/`）がある場合は、プロジェクト編集ダイアログの **「XServer側の保護対象を設定…」** から任意で追加できます。**「XServerから一覧を取得…」** を使うと、実際の同期先ルート直下から選択できます。必要な場合だけ **「サブフォルダも含めて取得…」** で配下も読み込みます。
2. **削除候補の一括操作と自動実行連携**:
   - ビルドごとにハッシュ付きアセット（`assets/index-xxxx.js` 等）が入れ替わり、古いファイルをまとめて削除したい場合は、手動の承認ダイアログまたは自動実行設定（**「リモートのみのファイル」→「確認画面で削除候補を選択する（削除時は自動バックアップ）」**）で表示される統合確認ダイアログから、**「削除候補をすべて選択」** / **「削除候補をすべて解除」** ボタンで一括選択できます（「削除しないフォルダー」に指定したフォルダは安全のため除外されます）。

## 5. プロジェクト管理（新規作成・複製・編集・削除）

### 新規作成（「新規…」ボタン）
- 「新規…」を押すとプロジェクト作成ダイアログが開きます。
- 画面上部の **「入力項目の確認方法」** を押すと、XServerサーバーパネルのどの画面から値を取得すればよいか詳細なヘルプが表示されます。

### プロジェクトの複製（「複製…」ボタン）
同じ XServer 上の別ドメインや、検証環境・本番環境で同じ接続設定を再利用したい場合に便利です。
- **メイン画面から**: プロジェクトを選んで **「複製…」** を押す。
- **編集画面から**: 「編集…」を開き、上部の「入力項目の確認方法」の左側にある **「複製…」** を押す。
- **動作**:
  - 全ての設定（SSHホスト、秘密鍵、確認コード、パスマッピング等）が引き継がれます。
  - プロジェクト名は `元の名前 のコピー`（重複時は `〜 のコピー 2`）として自動設定。
  - 保存すると新しいプロジェクトとして登録され、メイン画面で自動選択されます。

### プロジェクトの編集（「編集…」ボタン）
- 接続先、リモートパス、マッピングをいつでも変更できます。保存済みプロジェクトの主要項目（サイト種別・ドメイン・ルートパス・接続情報）は誤編集防止のため既定でロックされており、変更時のみロック解除して編集します。

### プロジェクトの削除（「削除」ボタン）
- 設定情報のみをローカルDBから削除します。XServer側およびローカル側のファイルには一切影響しません。

## 6. 同期モードと実行パイプライン

### 1. 安全同期を自動実行（推奨）
以下の4フェーズを完全自動で実行します（プロジェクトごとにメイン画面の **「自動実行設定…」** ボタンまたはメニューの **「設定」→「自動実行設定…」** でバックアップ方針（`必ず作成する` / `追加ファイルだけならスキップ` / `常にスキップ（復元不可）`）、`REMOTE_ONLY` 扱い（`残す` / `確認画面で選択` / `停止`）、HTTPS確認パス、変更上限をカスタマイズできます。現在の設定はメイン画面のボタン左側に常時表示されます）：
1. **フェーズ 1/4 (ドライラン)**: ローカルとリモートを走査し、変更計画（Plan）を生成。
2. **統合確認・承認ダイアログ**: 差分サマリーと安全上限を確認し承認します。**「バックアップ作成をスキップする（上書き前の状態には復元できません）」** のチェックでその回のバックアップ有無を切り替えられ、スキップ時に **「次回以降もこのプロジェクトの自動実行設定でバックアップを常にスキップする」** を選択して設定へ保存することもできます（`REMOTE_ONLY` の削除候補を選択した場合は、退避のためバックアップが自動的に必須となります）。
3. **フェーズ 2/4 (計画を再検証)**: 生成した計画が現在のリモートファイルと乖離していないか再確認。
4. **フェーズ 3/4 (バックアップを作成)**: 変更・削除対象となるリモートファイルのみをサーバー上に `.bak` として事前退避（スキップ時はこの段階を省略）。
5. **フェーズ 4/4 (承認済み同期)**: `.new` テンポラリファイル経由でファイルを転送し、一括アトミックリネームと任意のHTTPSヘルスチェックを実行。

### 2. 読み取り専用ドライラン
- リモートファイルを一切変更せず、差分ファイルの一覧と状態のみを表示します。
- 生成された同期計画は既定で **15分間** 有効です。メニューの **「設定」→「計画の有効時間設定…」** から **1〜60分** の範囲で選択・変更できます。

### 3. 承認付き同期
- ドライラン結果を確認した上で、承認ダイアログで変更対象や削除候補（「削除候補をすべて選択」/「削除候補をすべて解除」を含む）を選択して反映できます。

### 4. 無条件上書き
- ドライランや計画承認をスキップし、ローカルの内容でリモートを強制上書きします（転送済みファイルは記録され、中断時の再開も可能）。

## 7. 一時停止・アプリ終了後のリジューム（再開）

### 処理中の一時停止（「処理を停止」ボタン）
- 画面右下の **「処理を停止」** ボタンを押すと確認ダイアログが表示されます。
- 「はい」を選ぶと、**実行中の1ファイルが完了した安全な境界** で停止します。
- 転送途中の中途半端なファイルは自動削除されるため、壊れたファイルが本番に残ることはありません。

### アプリ終了・再起動後のリジューム（再開）
万が一、転送途中でネットワークが切断されたり、アプリを終了・PCをシャットダウンした場合でも、簡単に途中から再開できます：

1. **独自 PHP / 静的サイト / 通常同期**:
   - 次回起動時、中断された処理が自動検知され、上部に **「中断した処理を再開…」** ボタンが表示されます。
   - 計画情報がローカル SQLite に保存されているため、未転送分のみを即座に再同期できます。
2. **WordPress**:
   - 上部パネルの **「中断したセットアップを再開…」** をクリック。
   - 完了済みのDB作成やSQLインポートはスキップされ、未転送のファイルから継続されます。
3. **Laravel**:
   - 上部パネルの **「中断したセットアップを再開…」** をクリック。
   - 配置済みファイルを 0.2 秒で高速スキャンし、残りのファイル転送や未完了コマンドから再開されます。

## 8. 安全性確認・バックアップ・ロールバック・アップデート確認

### 安全性確認（クリーンアップスキャン）
- メイン画面の **「安全性確認」** ボタンを押すと、XServer 上を高速検査します。
- 過去の異常終了等で残ってしまった `.new` 一時ファイルや、不要になった古い `.bak` バックアップファイルを検出し、ワンクリックで安全に削除・整理できます。

### 履歴・ロールバック・古いバックアップの整理（「履歴…」ボタン）
- 過去に実行したすべての操作（同期、無条件上書き、セットアップ、バックアップ削除）が記録されています。
- 各履歴を選択して **「バックアップから復元」** を押すと、その同期で退避されたファイルを使って過去の状態へ即座に巻き戻す（ロールバックする）ことができます。
- **バックアップの保持整理（プルーン）**: バックアップタブ上部の **「保持件数（最新）」**（既定: 10件）と **「保持日数」**（既定: 30日）を設定して **「保持ルールで整理候補を選択」** を押すと、両条件を満たさない古いバックアップのみに削除チェックが付きます（最新件数・日数内のバックアップは保護されます）。内容を確認して削除ボタンを押すと、サーバー側バックアップを承認付きで整理できます。

### アプリ内アップデート確認
- メニューの **「ヘルプ」→「アップデートを確認…」** を実行すると、GitHub Releases 上の最新バージョンをバックグラウンドで確認し、更新がある場合はリリースノートへのリンクを案内します。

## 9. セキュリティと認証情報の保護

### ホスト鍵フィンガープリントの検証
- 初回接続時、入力された確認コード（SHA256）と XServer のホスト鍵を厳密に照合します。
- 不一致の場合は接続を即座に遮断し、なりすましや中間者攻撃（Man-in-the-Middle）を防ぎます。

### SSH 秘密鍵パスフレーズの保護（セッション保持 / オプトイン保存）
- アプリ起動中に一度入力したパスフレーズはメモリ上のセッションキャッシュに保持されるため、同じ起動中にドライラン・再検証・バックアップ・同期で繰り返し入力する必要はありません。
- 必要な場合のみ、パスフレーズ入力欄の **「パスフレーズをOS資格情報ストアに保存」** にチェックを入れることで、Windows 資格情報マネージャー / macOS キーチェーン / Linux Secret Service へ暗号化保存できます（チェックを外すと保存済みパスフレーズを即座に削除します）。

### 接続情報のマスキング（ショルダーハック防止）
- パスワード、秘密鍵パス、確認コードなどの機密情報は既定で `●●●●` とマスク表示されます。
- 一時的に確認したい場合は **「接続情報のマスクを一時解除」** にチェックを入れます。
- メニューの「設定」→「接続情報のマスク設定…」から、項目ごとにマスクの有無をカスタマイズできます。

## 10. トラブルシューティング & FAQ

### Q. SSH接続で「ホスト鍵が一致しません」というエラーが出る
- **原因**: サーバーパネルに記載された「確認コード（SHA256:...）」と入力値が一致していません。
- **対処**: XServer サーバーパネルの「SSH設定」→「SSHソフト設定」を開き、SHA256から始まるフィンガープリントをコピーして入力欄に貼り付けてください。

### Q. Laravel の同期・セットアップで `platform_check.php` エラーが出る
- **症状**: `Composer detected issues in your platform: Your Composer dependencies require a PHP version ">= 8.4.1". You are running 8.3.36.`
- **原因**: XServer のドメイン設定（PHP Ver.切替）またはウィザードで指定した PHP CLI のバージョンが、`composer.json` が要求するバージョンより低くなっています。
- **対処**:
  1. XServer サーバーパネルの「PHP Ver.切替」で対象ドメインを最新の PHP バージョン（PHP 8.4 など）に変更します。
  2. ウィザードの「PHP CLI バージョン」で一致するバージョン（例: `/usr/bin/php8.4`）を選択して再実行してください。

### Q. 同期から除外したいファイル・フォルダがある
- プロジェクト直下の `.git/`、`.env`、`compose.yml`、`node_modules/` などは自動除外されます。
- **「XServer側の保護対象を設定…」** から、XServer側で同期処理の対象にしないファイル／フォルダを指定できます。保護対象は読み取り・比較・バックアップ・復元・アップロード・削除から除外されます。パスの直接入力に加え、**「XServerから一覧を取得…」** で同期先ルート直下から選択できます。サブフォルダ内の項目を個別に選ぶ場合だけ、一覧画面から追加取得します。

## 11. CLI（コマンドライン）モード

本ツールは GUI だけでなく、CI/CD パイプライン、スクリプト、ターミナルからの完全ヘッドレス実行に対応しています。すべてのコマンドで `--json` オプションを付与することで、スクリプトや AI が処理しやすい構造化 JSON 出力が得られます。

```bash
# プロジェクト一覧を表示（JSON形式も可能）
dxsync project list [--json]

# プロジェクトの詳細設定やパス設定を確認
dxsync project show <プロジェクト名|ドメイン|ID> [--json]

# 読み取り専用ドライラン（リモートへの変更なし）
dxsync run dry-run <プロジェクト> [--mapping <マッピング名>] [--validity-minutes <1-60>] [--json]

# 安全同期（4段階パイプライン）を実行
# 対話プロンプトでは確認を入力。スクリプト・AI・非対話環境では --yes (-y) が必須
# --backup-mode (always|add_only|skip), --remote-only-policy (keep|stop|ask), --delete-path 等を指定可能
dxsync run auto-sync <プロジェクト> [--mapping <マッピング名>] \
  [--backup-mode always|add_only|skip] \
  [--remote-only-policy keep|stop|ask] [--delete-path <相対パス>] \
  [--health-check-path /] [--no-health-check] [--validity-minutes <1-60>] \
  [--max-changed-files <N>] [--max-update-files <N>] [--max-upload-mib <N>] \
  [--yes] [--json]

# 残留一時ファイル（.new）の検査と自動クリーンアップ
dxsync run verify <プロジェクト> [--cleanup] [--json]

# サーバー側バックアップ履歴の確認
dxsync backup list <プロジェクト> [--json]

# 指定バックアップからの復元（ロールバック）
# 対話プロンプトでは確認を入力。非対話環境では --yes (-y) が必須
dxsync backup restore <プロジェクト> --backup-id <ID> [--yes] [--json]

# 保持ルールに基づく古いバックアップの整理候補確認（--dry-run）または削除（--yes）
dxsync backup prune <プロジェクト> [--keep-latest 10] [--max-age-days 30] [--dry-run | --yes] [--json]
```

## 12. AI / MCP 連携と自動化（Antigravity, Claude, Cursor 等）

Docker → XServer Sync は **Model Context Protocol (MCP)** に対応しており、AI エージェントからの安全な遠隔操作が可能です。

### 12-1. 安全設計の原則
- **GUIでの安全な初期設定**: SSHホスト、ポート、秘密鍵パス、確認コードなどの機密情報は GUI で保存され、OS資格情報ストア（Keychain / Credential Manager）で保護されます。
- **AIからの操作範囲**: AI は保存済みプロジェクトの「一覧・詳細参照」「ドライラン」「安全自動同期（auto-sync）」「安全性確認・ゴミ掃除」「バックアップ一覧・復元・保持整理（既定 `dry_run=true`、実削除時は `confirm_delete=true` 必須）」のみを安全に実行できます。
- **一発安全同期パイプライン**: AIが `dxsync_auto_sync` を呼ぶと、内部で「ドライラン走査 → 計画再検証 → 自動リモートバックアップ → アトミック転送 → HTTPSヘルスチェック」が全自動かつ安全に実行されます（`backup_mode`、`remote_only_policy`、`delete_paths`、`plan_validity_minutes`、安全上限の各パラメータも指定可能）。

### 12-2. MCP サーバーの起動と設定
本ツールにはゼロ依存の stdio MCP サーバーが組み込まれています。

```bash
# MCPサーバーを標準入出力モードで起動
dxsync mcp
```

#### Claude Desktop / Cursor の設定例 (`claude_desktop_config.json`)
```json
{
  "mcpServers": {
    "docker-xserver-sync": {
      "command": "dxsync",
      "args": ["mcp"]
    }
  }
}
```

#### Antigravity CLI / IDE スキル (`/docker-xserver-sync`)
リポジトリ直下の `skills/docker-xserver-sync/` または `.gemini/skills/docker-xserver-sync/` を配置することで、Antigravity CLI や IDE から直接スキルとして認識されます。

```markdown
ユーザー: 「example.com のプロジェクトをドライランして、問題なければ同期して」
AI: dxsync_dry_run を実行して差分を確認後、dxsync_auto_sync を呼び出して安全に同期を完了します。
```
