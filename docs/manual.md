## 1. 全体設計思想と安全機能

Docker → XServer Sync は、ローカルの Docker コンテナ環境と XServer 本番環境の「差分」を埋め、事故を起こさずに同期することを目的として設計されています。

### 主な安全設計
- **読み取り専用ドライラン**: サーバーに変更を加えることなく、追加・更新・削除・競合ファイルを事前に完全走査。
- **4段階自動同期パイプライン**: 「ドライラン」→「計画の再検証」→「変更前ファイルの自動バックアップ」→「明示承認後の安全同期」を1クリックで完結。
- **アトミック書き込み**: ファイル転送時は一時ファイル（`.new`）へ転送した後にリネームするため、通信断や強制終了時もファイルが破損しません。
- **自動除外と本番データ保護**: `.git`、`.env`、開発用 `compose.yml`、`node_modules/` などの秘密・不要ファイルは既定で除外。サーバー上の `uploads/` や `storage/` などの動的ファイルは削除・上書きから保護されます。
- **OS資格情報ストア連携**: SSH接続先の確認コード（ホスト鍵 SHA-256 フィンガープリント）は平文で保存せず、Windows 資格情報マネージャー、macOS キーチェーン、Linux Secret Service に安全に保管。中間者攻撃（MITM）を確実に防止します。

## 2. 動作環境と事前準備（XServer 側・ローカル側）

### 動作環境
- **対応OS**: Windows 10 / 11 (x64), macOS 12+ (Apple Silicon arm64 / Intel x86_64), Linux (x86_64)
- **ネットワーク**: XServer の SSH ポート（通常 `10022`）へ接続可能なインターネット環境

### XServer 側の準備手順
1. **XServer サーバーパネルへログイン**:
   - 「SSH設定」を開き、SSH接続を **「ON（有効）」** に設定します。
2. **SSH 鍵の取得**:
   - 「公開鍵認証用鍵ペアの生成」でパスフレーズを指定して鍵を生成し、秘密鍵（`.key` ファイル）を PC にダウンロードします。
3. **接続情報の確認**:
   - 「SSHソフト設定」画面で以下を確認します：
     - **SSHホスト**: `SERVER_ID.xsrv.jp`
     - **SSHユーザー**: `SERVER_ID`（サーバーID）
     - **SSHポート**: `10022`
     - **確認コード**: `SHA256:...` から始まるホスト鍵フィンガープリント

### ローカル（Docker / PC）側の準備
- 同期元フォルダとして、PC上のローカルパスを指定します。
- `compose.yml` 内で `volumes: ./src:/var/www/html` と指定されている場合は、PC上の `./src` の絶対パスを指定します。

### 操作ボタン一覧
- **新規…**: 新規プロジェクトを作成します。
- **複製…**: 選択中のプロジェクト設定を引き継ぎ、新しいプロジェクトとして複製します。
- **編集…**: 接続情報やパスマッピング、保持パス設定を編集します。編集ダイアログ内にも「複製…」ボタンが用意されています。
- **削除**: 保存済みプロジェクト設定を削除します（ローカル・リモートの実体ファイルは一切削除されません）。
- **安全性確認**: XServer 上に残存している一時ファイル（`.new`）や期限切れバックアップを検出・一括掃除します。
- **履歴…**: 過去の同期・リストア履歴を閲覧し、バックアップからのロールバックを実行できます。
- **安全同期を自動実行**: 推奨される同期方式です。ドライラン・再検証・バックアップ・反映の全自動パイプラインを実行します。
- **読み取り専用ドライラン**: サーバーを変更せずに差分のみを取得・一覧表示します。
- **処理を停止**: 同期・セットアップ処理を直近の安全なファイル境界で中断します。

## 4. サイト種別ごとの設定と運用ガイド

### 4-1. 独自 PHP サイト
WordPress や Laravel 以外の PHP サイトです。

1. **設定手順**:
   - サイトの種類に **「独自 PHP（上記以外）」** を選択。
   - 同期フォルダの「保持パス設定…」を開きます。
   - `uploads/`、`storage/`、`cache/`、`logs/`、`tmp/` は自動保護されます。
   - `userfiles/` や `data/sessions/` など、サイト固有の本番書き込み先があれば追加し、**「設定内容を確認し、本番での書き込み先を保護することに同意します」** にチェックを入れて保存します。
2. **日常の同期**:
   - 「安全同期を自動実行」を押すだけで、保護フォルダを維持したままプログラムコードのみを安全に同期します。

---

### 4-2. WordPress サイト
WordPress サイトの初回移行と日常同期をサポートします。

#### 初回セットアップウィザード
Docker 環境の WordPress を空の XServer ドメインへ移行します。
1. **事前準備**:
   - Docker の MySQL から `.sql` ダンプファイルを出力しておきます。
   - XServer のサーバーパネル「MySQL設定」で空のデータベースとユーザーを作成します（または XServer API を利用）。
2. **ウィザードの実行**:
   - 上部パネルの **「セットアップを開始…」** をクリック。
   - **SQLファイルの選択**: 用意した `.sql` を指定。
   - **対象ファイルの選択**: コアファイル、テーマ、プラグイン、uploads の転送対象を確認。
   - **データベース情報**: MySQLホスト（通常 `localhost`）、DB名、ユーザー、パスワード、公開URLを入力。
   - **PHP CLI バージョン**: サーバーパネルの PHP バージョンに合わせます（既定: PHP 8.3）。
   - **実行**:
     - DBテーブルの重複チェック（既存テーブルがあれば安全のため中断）
     - SQLダンプの転送・インポート
     - WordPressファイルの転送
     - `wp-config.php` の自動生成・配置
     - WP-CLI による URL 置換（ローカル URL → 本番ドメイン URL）
     - 初期 `index.html` の自動削除
     - HTTPS ヘルスチェック（トップページおよび `/wp-login.php` の 200 OK 確認）

#### 日常の同期
- 初回セットアップ完了後は、通常の「安全同期を自動実行」を使用します。
- `wp-config.php` や `wp-content/uploads/` は保護対象として維持され、ローカルの変更（テーマやプラグインの更新）のみが安全に反映されます。

---

### 4-3. Laravel サイト
Laravel サイトの分割配置・初回デプロイ・差分同期をサポートします。

#### 推奨ディレクトリ構成
セキュリティのため、Web公開フォルダとアプリケーション本体を分離して配置します。
- **Laravel本体（アプリルート）**: `/home/SERVER_ID/example.com_app`
- **公開ディレクトリ（公開ルート）**: `/home/SERVER_ID/example.com/public_html`

#### 初回セットアップウィザード
1. **ウィザードの起動**:
   - 画面上部パネルの **「セットアップを開始…」** をクリック。
2. **設定項目の入力**:
   - **DB接続方式**: 作成済みDBの指定（ホスト、DB名、ユーザー、パスワード）。
   - **本番APP_URL**: `https://example.com`
   - **PHP CLIバージョン**: 対象ドメインのPHPバージョンを選択（例: `/usr/bin/php8.3`）。
   - **マイグレーション**: `artisan migrate --force` の実行有無。
3. **自動実行内容**:
   - リモート高速一括スキャン（サーバー側配置状況を 0.2 秒で確認）
   - 本体ファイルおよび public ファイルの転送
   - 本番用 `.env` の自動生成・配置
   - APP_KEY 生成 (`php artisan key:generate --force`)
   - `storage` ディレクトリのパーミッション設定
   - シンボリックリンク作成 (`public/storage` → `storage/app/public`)
   - マイグレーション実行
   - HTTPS ヘルスチェック

#### 高速スキップ機能（v0.3.1+）
- Laravel の初回セットアップでは、SSH経由でリモートの配置済みファイルを一括スキャンします。すでに転送済みの同一ファイル（サイズ・更新日時一致）は自動でスキップされるため、数千〜1万件のファイルがあっても約20秒で高速同期が完了します。

## 5. プロジェクト管理（新規作成・複製・編集・削除）

### 新規作成（「新規…」ボタン）
- 「新規…」を押すとプロジェクト作成ダイアログが開きます。
- 画面上部の **「入力項目の確認方法」** を押すと、XServerサーバーパネルのどの画面から値を取得すればよいか詳細なヘルプが表示されます。

### プロジェクトの複製（「複製…」ボタン）
同じ XServer 上の別ドメインや、検証環境・本番環境で同じ接続設定を再利用したい場合に便利です。
- **メイン画面から**: プロジェクトを選んで **「複製…」** を押す。
- **編集画面から**: 「編集…」を開き、上部の「入力項目の確認方法」の左側にある **「複製…」** を押す。
- **動作**:
  - 全ての設定（SSHホスト、秘密鍵、確認コード、パスマッピング等）が引き継がれます。
  - プロジェクト名は `元の名前 のコピー`（重複時は `〜 のコピー 2`）として自動設定。
  - 保存すると新しいプロジェクトとして登録され、メイン画面で自動選択されます。

### プロジェクトの編集（「編集…」ボタン）
- 接続先、リモートパス、マッピングをいつでも変更できます。

### プロジェクトの削除（「削除」ボタン）
- 設定情報のみをローカルDBから削除します。XServer側およびローカル側のファイルには一切影響しません。

## 6. 同期モードと実行パイプライン

### 1. 安全同期を自動実行（推奨）
以下の4フェーズを完全自動で実行します：
1. **フェーズ 1/4 (ドライラン)**: ローカルとリモートを走査し、変更計画（Plan）を生成。
2. **フェーズ 2/4 (計画を再検証)**: 生成した計画が現在のリモートファイルと乖離していないか再確認。
3. **フェーズ 3/4 (バックアップを作成)**: 変更対象となるリモートファイルのみをサーバー上に `.bak` として事前退避。
4. **フェーズ 4/4 (承認済み同期)**: `.new` テンポラリファイル経由でファイルを転送し、一括アトミックリネーム。

### 2. 読み取り専用ドライラン
- リモートファイルを一切変更せず、差分ファイルの一覧と状態のみを表示します。

### 3. 承認付き同期
- ドライラン結果を確認した上で、承認ダイアログで除外したいファイルのチェックを外して反映できます。

### 4. 無条件上書き
- ドライランや計画承認をスキップし、ローカルの内容でリモートを強制上書きします（転送済みファイルは記録され、中断時の再開も可能）。

## 7. 一時停止・アプリ終了後のリジューム（再開）

### 処理中の一時停止（「処理を停止」ボタン）
- 画面右下の **「処理を停止」** ボタンを押すと確認ダイアログが表示されます。
- 「はい」を選ぶと、**実行中の1ファイルが完了した安全な境界** で停止します。
- 転送途中の中途半端なファイルは自動削除されるため、壊れたファイルが本番に残ることはありません。

### アプリ終了・再起動後のリジューム（再開）
万が一、転送途中でネットワークが切断されたり、アプリを終了・PCをシャットダウンした場合でも、簡単に途中から再開できます：

1. **独自 PHP / 通常同期**:
   - 次回起動時、中断された処理が自動検知され、上部に **「中断した処理を再開…」** ボタンが表示されます。
   - 計画情報がローカル SQLite に保存されているため、未転送分のみを即座に再同期できます。
2. **WordPress**:
   - 上部パネルの **「中断したセットアップを再開…」** をクリック。
   - 完了済みのDB作成やSQLインポートはスキップされ、未転送のファイルから継続されます。
3. **Laravel**:
   - 上部パネルの **「中断したセットアップを再開…」** をクリック。
   - 配置済みファイルを 0.2 秒で高速スキャンし、残りのファイル転送や未完了コマンドから再開されます。

## 8. 安全性確認・バックアップ・ロールバック

### 安全性確認（クリーンアップスキャン）
- メイン画面の **「安全性確認」** ボタンを押すと、XServer 上を高速検査します。
- 過去の異常終了等で残ってしまった `.new` 一時ファイルや、不要になった古い `.bak` バックアップファイルを検出し、ワンクリックで安全に削除・整理できます。

### 履歴とロールバック（「履歴…」ボタン）
- 過去に実行したすべての操作（同期、無条件上書き、セットアップ）が記録されています。
- 各履歴を選択して **「バックアップから復元」** を押すと、その同期で退避されたファイルを使って過去の状態へ即座に巻き戻す（ロールバックする）ことができます。

## 9. セキュリティと認証情報の保護

### ホスト鍵フィンガープリントの検証
- 初回接続時、入力された確認コード（SHA256）と XServer のホスト鍵を厳密に照合します。
- 不一致の場合は接続を即座に遮断し、なりすましや中間者攻撃（Man-in-the-Middle）を防ぎます。

### 接続情報のマスキング（ショルダーハック防止）
- パスワード、秘密鍵パス、確認コードなどの機密情報は既定で `●●●●` とマスク表示されます。
- 一時的に確認したい場合は **「接続情報のマスクを一時解除」** にチェックを入れます。
- メニューの「設定」→「接続情報のマスク設定…」から、項目ごとにマスクの有無をカスタマイズできます。

## 10. トラブルシューティング & FAQ

### Q. SSH接続で「ホスト鍵が一致しません」というエラーが出る
- **原因**: サーバーパネルに記載された「確認コード（SHA256:...）」と入力値が一致していません。
- **対処**: XServer サーバーパネルの「SSH設定」→「SSHソフト設定」を開き、SHA256から始まるフィンガープリントをコピーして入力欄に貼り付けてください。

### Q. Laravel の同期・セットアップで `platform_check.php` エラーが出る
- **症状**: `Composer detected issues in your platform: Your Composer dependencies require a PHP version ">= 8.4.1". You are running 8.3.36.`
- **原因**: XServer のドメイン設定（PHP Ver.切替）またはウィザードで指定した PHP CLI のバージョンが、`composer.json` が要求するバージョンより低くなっています。
- **対処**:
  1. XServer サーバーパネルの「PHP Ver.切替」で対象ドメインを最新の PHP バージョン（PHP 8.4 など）に変更します。
  2. ウィザードの「PHP CLI バージョン」で一致するバージョン（例: `/usr/bin/php8.4`）を選択して再実行してください。

### Q. 同期から除外したいファイル・フォルダがある
- プロジェクト直下の `.git/`、`.env`、`compose.yml`、`node_modules/` などは自動除外されます。
- 独自PHPの場合は「保持パス設定…」から本番で保持するパスを指定できます。

## 11. CLI（コマンドライン）モード

本ツールは GUI だけでなく、CI/CD パイプラインやターミナルからのスクリプト実行にも対応しています。

```bash
# プロジェクト一覧を表示
dxsync --list-projects

# 指定プロジェクトのドライランを実行
dxsync --project "example.com" --dry-run

# 指定プロジェクトの安全同期（自動実行）を実行
dxsync --project "example.com" --auto-sync
```
