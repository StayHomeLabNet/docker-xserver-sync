# 初回設定ガイド

## 1. サイトの種類

ローカルフォルダの中身で選ぶ。

| 選択肢 | 見分け方 |
|---|---|
| WordPress | `wp-content`、`wp-admin`、`wp-includes`がある |
| Laravel | `artisan`、`app`、`routes`、`public`がある |
| 独自PHP | 上記以外のPHPサイト |

この選択により、`uploads`や`storage`などXServer側で更新されるフォルダの保護ルールが変わる。

独自PHPを選んだ場合は、同期フォルダの行を選び、「本番書き込み先を設定…」を押す。`uploads/`、`storage/`、`cache/`、`logs/`、`tmp/`は自動保護される。`userfiles/`や`data/sessions/`などサイト固有の保存先がある場合は、1行に1つ、同期元ルートからの相対パスで追加する。追加の書き込み先がない場合も確認チェックが必要で、未確認のままではドライランや同期を実行できない。

## 2. PC側の同期元フォルダ

Dockerコンテナ内のパスではなく、PC上の実際のフォルダを選ぶ。

`compose.yml`または`docker-compose.yml`に次の記述がある場合:

```yaml
volumes:
  - ./src:/var/www/html
```

選択するのは左側の`./src`。右側の`/var/www/html`ではない。

WordPressなら通常は`wp-content`が見えるフォルダ、Laravelなら`artisan`が見えるフォルダを選ぶ。

## 3. SSHホストとSSHユーザー

XServerのサーバーパネルで「SSH設定」→「SSHソフト設定」を開いて確認する。

一般的な例:

```text
SSHホスト: SERVER_ID.xsrv.jp
SSHユーザー: SERVER_ID
SSHポート: 10022
```

独自ドメインではなく、SSH設定画面に表示されたホスト名を入力する。

## 4. ホスト鍵フィンガープリント

接続先が正しいXServerであることを確認する値。サーバーパネルの「SSH設定」→「SSHソフト設定」にある`SHA256:`から始まる文字列を、そのままコピーする。

例:

```text
SHA256:abcdefghijklmnopqrstuvwxyz1234567890ABCDE
```

アプリはこの値が一致しないサーバーへの接続を拒否する。

## 5. SSH秘密鍵

XServerへ公開鍵を登録した際にPCへ保存した秘密鍵ファイルを選ぶ。

- `SERVER_ID.key`、`id_ed25519`などのファイル
- `.pub`で終わる公開鍵は選ばない
- 秘密鍵の内容はSQLiteへ保存しない
- パスフレーズは実行時だけ入力し、保存しない

## 6. XServer側のテストフォルダ

本番の`public_html`直下ではなく、先にテスト専用フォルダを用意する。

例:

```text
/home/SERVER_ID/example.com/public_html/sync-test
```

正確な絶対パスはSSH接続後、対象フォルダへ移動して`pwd`を実行すると確認できる。

```bash
cd example.com/public_html/sync-test
pwd
```

読み取り専用ドライランはフォルダを作成しない。テストフォルダはXServerのファイルマネージャーまたはSSHで事前に作成する。

## 最初の接続試験

1. XServer側に空の`sync-test`フォルダを作る。
2. PC側は小さなテスト用フォルダを選ぶ。
3. プロジェクトを保存する。
4. 「読み取り専用ドライラン」を実行する。
5. XServer側に新しいファイルが作られていないことを確認する。

## テストディレクトリへの初回同期

1. ドライランの差分一覧と転送先を確認する。
2. 「計画を再検証」を押す。
3. 成功後だけ有効になる「バックアップを作成」を押し、専用領域への書き込みを確認する。
4. バックアップ完了後、「承認付き同期」を押す。
5. 転送先・変更内容・バックアップの確認欄を選び、表示されたドメインを正確に再入力する。
6. 同期後にもう一度ドライランし、意図したファイルが`SAME`になったことを確認する。

同期対象はまずテストディレクトリに限定する。リモートにだけ存在するファイルは削除候補として表示されるが、初期状態はすべて未選択で削除されない。「バックアップを作成」画面で個別に選択し、バックアップ後の最終承認画面で削除件数を再確認した場合だけ削除される。

XServer側が空の場合でも、通常は0ファイルのバックアップマニフェストを作成して同期へ進める。「バックアップを作成」画面でスキップを選ぶこともできるが、同期前の状態へ復元できなくなる。スキップ時は削除を選択できない。

削除候補がフォルダー内にある場合は、「削除しないフォルダー」をチェックすると、そのフォルダー以下の候補は削除対象から外れる。

「無条件上書き」は初回配置用の緊急経路で、確認画面のツリーから上書きするフォルダーまたはファイルを選択できる。「すべてチェック」「すべてチェック解除」で一括変更もできる。ドライラン計画、リモート内容照合、バックアップ、転送後ハッシュ検証を行わずに、選択したローカルファイルだけを上書きする。未選択ファイル、除外・保護対象、リモートにしかないファイルは残る。通常の更新では「承認付き同期」を使用する。

## 安全同期の自動実行

「設定」→「自動実行設定…」で、選択中のプロジェクトについてバックアップ方式、REMOTE_ONLYの扱い、HTTPS確認パス、最大変更件数・UPDATE件数・転送量を設定できる。「安全同期を自動実行」を押すと最初に読み取り専用ドライランを行い、設定上限内なら変更概要と実行設定をまとめて表示する。対象ドメインを再入力して一度承認すると、再検証、バックアップ、同期を自動的に継続する。

自動実行ではREMOTE_ONLYを削除しない。「存在したら停止」を選んだ場合は書き込み前に終了する。無条件上書きへ自動移行することもない。バックアップをスキップする設定では、統合確認画面に復元不可であることを表示する。処理中はプロジェクト・同期対象・接続設定を変更できない。

## 画面表示と確認コードの保護

接続先の確認コードはプロジェクト保存時にOS資格情報ストアへ格納され、SQLiteには参照名だけを保存する。資格情報ストアへ保存・移行できない場合は、読み取り専用ドライランを含む同期操作を禁止する。「設定」→「接続先の確認コードを再登録…」から復旧できる。

「設定」→「接続情報のマスク設定…」では、起動時に伏せ字にする接続項目を選べる。画面の「接続情報のマスクを一時解除」は表示だけを一時変更し、設定や値を別の場所へ保存しない。パスフレーズはプロジェクト設定へ保存されず、起動時は常にマスクされる。
